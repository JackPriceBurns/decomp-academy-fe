# How ~x compiles, and when it disappears

`mvn Rd, Rs` writes the bitwise complement of `Rs` into `Rd`. It is the direct
translation of C's `~`:

```asm
0        mvn       r0, r0
2        bx        lr
```

`neg` is a different instruction for a different operator. The two often
appear next to each other, so it is common to confuse them in a listing:

```asm
0        neg       r0, r0
2        bx        lr
```

That one is `-x`, an arithmetic negation. The two values differ by exactly one:
`~x` is `-x - 1`. If you read the wrong one, you get a mismatch of a single
instruction, and that is very hard to spot.

You might expect the compiler to notice that `~x + 1` is the same value as
`-x`, and to emit the shorter form. It does not:

```asm
0        mvn       r0, r0
2        add       r0, #1
4        bx        lr
```

That is two instructions, where one `neg` would have been enough. gcc 2.9's
simplifier is good at pure boolean algebra. It is much weaker on identities that
mix bitwise and arithmetic operators, so here you get exactly what you write.

The other half of reading `mvn` is knowing when it will *not* appear. A
complement of a register on either side of an `&` is absorbed into a `bic`. A
complement of a literal is absorbed by complementing the literal itself. Neither
`orr` nor `eor` has a complementing form. So a `~` that feeds one of those
cannot be absorbed, and you see a real `mvn` in the listing. When the
instruction is there, it tells you what the complement was combined with.
