# Turning bits on

`orr Rd, Rs` follows the same rules as `and`. It takes two operands, it
overwrites the first one, and it has no immediate form. So setting bits with a
constant costs a `mov` to build the constant, and then the `orr` itself. The
constant goes into the destination register.

```asm
0        mov       r0, #48
2        orr       r0, r1
4        bx        lr
```

That function ors `0x30` onto its second argument. This is the cheap case,
because nothing had to move out of the way.

When both operands are registers, there is no constant to build, and the whole
body is one instruction:

```asm
0        orr       r0, r1
2        bx        lr
```

Keep this in mind while you read listings. A bare `orr` between two argument
registers is the whole body, and every extra `mov` in the listing is building a
constant.

Now count the constants. gcc 2.9 simplifies bitwise expressions before it picks
instructions. One of the rewrites it knows is merging two masks of the same
variable: `(a & 3) | (a & 0x0C)` becomes a single `and` with 15, which needs one
`mov` and one constant. It knows only a few rewrites like this, mostly a
constant meeting another constant through the same operator. So in most
listings, every constant the author wrote stays as its own `mov`.

This means the constants that `mov` builds in the listing are a good count of
the constants in the original C. Your target has two, and the order they are
built in tells you which operation ran first.

## Your task

Write `func_080d2f04` to reproduce the target assembly.

<!-- solution -->
```c
u32 func_080d2f04(u32 v) {
    return (v & 15) | 0xF0;
}
```
