# The instruction that clears flags

`bic Rd, Rs` computes `Rd &= ~Rs`. The complement comes for free, because it is
part of the instruction, so no `mvn` appears in the listing. You will see this
shape whenever a mask held in a variable says which bits to turn off:

```asm
0        bic       r0, r1
2        eor       r0, r2
4        bx        lr
```

This function takes three arguments. It uses the second one as a mask of bits
to clear, and then xors the third one on. The `bic` is a single instruction
because the mask is in a register and the value is already in the destination.
For once, the two-operand form that overwrites its destination is exactly what
is needed, and nothing has to be moved out of the way.

The order of the operands in the C makes no difference here. `a & ~b` and
`~b & a` both compile to the same single `bic`. That is unusual for this
compiler, and worth remembering when you are trying different ways to write
the C.

A constant mask compiles differently, and the difference is important:

```asm
0        mov       r1, r0
2        mov       r0, #16
4        neg       r0, r0
6        and       r0, r1
8        bx        lr
```

That function clears the low four bits of its argument, and there is no `bic`
at all. With a constant, the compiler complements the *constant* instead. The
mask it needs is `0xFFFFFFF0`. Because `mov` can only load an 8-bit value, the
compiler builds this mask by moving 16 into a register and negating it. Then it
uses a plain `and`. So `bic` in a listing means the mask was a variable, and
`and` after a `neg` means the mask was a literal.

## Your task

Write `func_080dbde0` to reproduce the target assembly.

```c
u32 func_080dbde0(u32 v, u32 m) {
    return (v & ~m) | 2;
}
```
