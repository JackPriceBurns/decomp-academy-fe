# Flipping bits

`eor` is the third member of the family, and it has the same shape as `and` and
`orr`. `eor Rd, Rs` means `Rd ^= Rs`. It has no immediate form, and the
constant goes in the destination. Against another register it is one
instruction:

```asm
0        eor       r0, r1
2        bx        lr
```

Read that as "which bits of these two values differ". Against a constant, you
pay for building the constant. You also pay for a `mov` that moves the value out
of `r0`, if it came in as the first argument:

```asm
0        mov       r1, r0
2        mov       r0, #128
4        eor       r0, r1
6        bx        lr
```

`eor` differs from `and` and `orr` in one way: it is its own inverse. If you
apply the same mask twice, you are back where you started, and gcc 2.9 knows
this. A function that flips `0x3C` and then flips `0x3C` again compiles to this:

```asm
0        bx        lr
```

The whole body is gone. This is worth learning early. If your C contains an
identity that the compiler can see through, the instructions you expected will
not be there.

The other thing you will see all the time on the GBA is a bit chosen at run
time, instead of one written as a literal. Then there is no constant to build.
The mask is *computed* by putting a 1 in a register and shifting it up. When you
see a `mov rN, #1` followed by a shift whose amount is a register, read the pair
as one value: the single bit at that position.
