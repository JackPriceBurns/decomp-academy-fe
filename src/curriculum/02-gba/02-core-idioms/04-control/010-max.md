# When both answers arrive in registers

In the previous lesson, a constant was put in a register as the seed before the
compare, and then overwritten when the condition was true. The same pattern
handles a choice between two values that both arrive in registers. The part to
watch is the register that collects the result (the accumulator).

```asm
0        cmp       r0, r1
2        ble       6 ~>
4        mov       r1, r2
6      ~>mov       r0, r1
8        bx        lr
```

The result is built in `r1`, which already holds one of the two candidates.
That candidate needs no seed, because it is already where it needs to be.
`mov r1, r2` is the overwrite. `ble` skips it when the condition in the source
is false, and `mov r0, r1` returns whatever is left in `r1`. That is five
instructions, with no join branch.

If you write the same decision as an `if` with a return in each arm, the code is
longer:

```asm
0        cmp       r0, r1
2        bgt       8 ~>
4        mov       r0, r1
6        b         10 ~>
8      ~>mov       r0, r2
10     ~>bx        lr
```

There is no accumulator here. Each arm moves its own answer straight into `r0`,
and the arm placed first has to jump over the second. So each candidate needs
one instruction, and the join needs a third. The decision and the two values
are the same, but this version has six instructions instead of five.

The pattern to watch for is when the accumulator has to be `r0` itself. `r0`
arrives holding the first argument. To build anything else there, the compiler
must first move that argument out. So the function starts with a pair of
`mov`s: one copies an argument to a scratch register, and the second puts the
remaining argument in `r0`. After that pair, `r0` holds the value the function
returns when the branch is taken and nothing else runs. The scratch register
holds the answer that needs a `mov`.

Read that pair before you read the compare. It tells you which of the two values
needs no extra instruction. It also tells you what the compare's operands mean.
The same two register numbers can mean opposite things, depending on which way
the moves went.

Your target starts with that pair. Work out which value ends up in `r0`. Then
read the compare and its branch together to find the condition that leaves it
there.
