# The optimizer spots the repeat

If you write the same subexpression twice, IDO computes it once. This is
**common subexpression elimination** (CSE). It means the instruction count in
the target won't match the operator count in your C. Here is `sq(a, b)`, which
returns `(a + b) * (a + b)`:

```asm
addu   v1, a0, a1   # a + b: ONE addu for two mentions
multu  v1, v1       # …times itself
mflo   v0
nop
nop
jr     ra
nop
```

The source has two `(a + b)`s, and the machine code has one `addu`. The shared
value is kept in `v1` and feeds both `multu` operands. This also works in the
other direction, when you write C from assembly: **a register used in several
places can be the same subexpression written several times**. You don't need a
temp variable to make that happen. (You *may* use one:
`s32 t = a + b; return t * t;` compiles to the same listing. Pick whichever
reads better. The compiler turns both into the same form.)

When you match a target like this, the sign to look for is a register that
several instructions read. Find what computed it. Each instruction that reads
it is another mention of that subexpression in your C.

The target computes one combination of its arguments and uses it twice: once
as it is, and once shifted. Find the shared register, then read the second
hint.

## Your task

Write `func_801fa5a4` to reproduce the target assembly.

<!-- solution -->
```c
s32 func_801fa5a4(s32 a, s32 b) {
    return (a | b) + ((a | b) >> 4);
}
```
