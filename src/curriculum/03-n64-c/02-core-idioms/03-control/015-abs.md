# The negu diamond

Some diamonds are so common that you read them as a single word. Here is a
simpler relative of one of them first: a helper that negates its second
argument when a flag is set, `if (f) x = -x; return x;`:

```asm
 0:  beqzl a0, 0x10      # flag clear? keep x unchanged...
 4:  or    v0, a1, zero  # (likely slot) the as-is copy, taken path only
 8:  negu  a1, a1        # flag set: flip the sign
 c:  or    v0, a1, zero
10:  jr    ra
14:  nop
```

You have known `negu` since the warmup: it computes `0 - x`, the negation.
When it is guarded by a condition and if-converted onto a likely branch, it
means "maybe negate". This is the duplicated copy to `v0` from the
branch-likely lesson, with `negu` as the guarded work.

Now use a *sign test* to control that same negation, and you get one of the
most recognizable idioms in compiled C: absolute value, "if it's negative,
negate it". The target below is exactly that. IDO compiles it as the full
ternary diamond instead of the likely form. A `bgez` chooses between two arms,
one a copy and the other a `negu`, and both meet in `v1` before the join
copies to `v0`.

There are two ways to write matching C for that shape:

```c
if (x < 0) { ... }   /* statement form */
return x < 0 ? ... : ...;   /* expression form */
```

Both compile to the same code here, because the diamond does not depend on
how the C is written. What does matter is that the branch is `bgez`, so the
fall-through (not taken) path is the negative case. Find which arm holds the
`negu`, and make your condition agree.

## Your task

Write `func_802964ac` to reproduce the target assembly.

<!-- solution -->
```c
s32 func_802964ac(s32 x) {
    return x < 0 ? -x : x;
}
```
